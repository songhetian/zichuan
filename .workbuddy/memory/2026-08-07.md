## 表格表头与内容错位修复 (TDD)
- **现象**: 表格内数据列与表头列对不齐(横向错位)。
- **根因**: `data-table.tsx` 的 `<Table>` 用浏览器默认 `table-auto` 布局；上一轮给 th/td 写的 `style.width` 在 `table-auto` 下只是"最小宽度建议",浏览器仍按内容重分配,叠加表头 `sticky` + 外层 `overflow-auto` 滚动条抢占空间 → 表头列宽与数据列宽算出不同。
- **修复**: `<Table>` 加 `table-fixed` 类,列宽严格按 th/td 的 width 走,表头与内容像素级对齐;同时移除 th 上 `table-auto` 时代的 `min-w-[80px]` 兜底(会被 table-fixed 的 min-width 盖过 width,把 select40/ID60 撑宽,反而不紧凑)。
- **测试**: 新增 `tests/data-table-alignment.test.tsx`(3 项,红→绿)；既有 `data-table-style`(7)+ 列表页受影响测试(24) 全绿,tsc 干净。
- **影响**: table-fixed + w-full 下列不再塌缩；窄屏多列时可能出横向滚动条(容器内 overflow-auto 正常行为,优于错位)。
- 用户同日决定: git 自行手动提交;**深色模式明确不做**(已写入 MEMORY.md)。

## 表格错位修复补全 (脱离 DataTable 的列表页)
- **现象**: 仅设备列表(走共享 DataTable)对齐正常,其余列表页仍错位。
- **范围排查**: `DataTable` 被 8 个页面引用(员工/日志/库存流水/型号/配件/资产/盘点/模板),均已随上轮 table-fixed 修复。但有三处列表页**未用 DataTable**:

- **根因**: 与 DataTable 之前一致,`table-auto` 下浏览器按内容重分配列宽,表头短中文 vs 数据长文本 → 错位。TreeTable 还有 `className={col.width ? \`w-${col.width}\` : ""}` 动态拼接死类名(Tailwind purge 后无效,宽度只靠 inline style)。
- **修复**:
  - `tree-table.tsx`: `<Table>` 加 `table-fixed`;列宽 `style.width` 同时写到 th 与 td(去掉死类名);操作列 th/td 均 `w-24`。
  - `departments-client.tsx`: `<Table>` 加 `table-fixed`,操作列 td 补 `w-[120px]` 与表头一致。
- **测试**: 新增 `tests/tree-table-alignment.test.tsx`(2 项,红→绿);相关 36 项前端测试全绿,tsc 干净。
- **注意**: 资产/配件分类页(asset-categories)的 4 列(分类名称/编码/分配规则/编号规则)未设显式 width,table-fixed 下均分剩余宽度,可能"分配规则"偏宽、"编号规则"偏窄——功能对齐已解决,如需更精致列宽可在页面 columns 加 `width` 字段(px)。

## 登录一会儿退出的诊断与修复 (TDD)
- **用户疑问**: 登录一会儿就自动退出,以为是 JWT 问题。
- **结论: 非 JWT**。项目用 `iron-session`(cookie session,`src/lib/auth.ts`),非 JWT。前端不会自动跳登录(header 仅在点「退出登录」时跳),自动退出必为服务端 `(main)/layout.tsx` 的 `getCurrentUser()` 读不到 session → `redirect("/login")`。
- **根因排序**: 用户确认**只用 IP(192.168.110.145)访问** → 排除 IP/域名混用导致 cookie 域不共享;部署纯 HTTP 且 `SESSION_SECRET` 已正确设置 → 排除 secret/secure 误设。最可能为**代码设计缺陷: iron-session 无滑动过期**(8h 固定到期,中间再活跃也不续,只读导航从不 `save`,cookie `Max-Age` 不刷新)。
- **修复**(`src/lib/auth.ts`):
  - `getCurrentUser()` 读到已登录 session 后,内层 try/catch 调 `session.save()` 实现**滑动过期**(活跃用户不再被固定 8h 踢);只读上下文(layout 服务端渲染)`save` 会抛错 → 静默跳过,一处改动覆盖所有调用点。
  - `getSession()` 读 `headers()` 的 `x-forwarded-proto` 动态设 `cookieOptions.secure`(**secure 动态化**): 当前 HTTP 下 false(行为不变),将来上 HTTPS 自动 true 兜底。
  - nginx「统一域名」因用户只用 IP 不适用,已跳过(强行 301 到域名会使其无法访问)。
- **测试**: 新增 `tests/session-sliding.test.ts`(4 项,红→绿,用 vi.hoisted 隔离 next/headers/iron-session/prisma);受影响前端测试 45 项全绿,tsc 干净。
- **用户自查提示**: 若部署后仍"几分钟就退出"(非 8h 到点),则可能非本修复范围——建议查浏览器 DevTools→Application→Cookies 看 `zichuan_session` 是否带 Max-Age 且稳定;或浏览器/公司策略清 cookie、隐身模式、某处误调 `destroySession`。
