## 修复 `npm run docker:deploy` 报错 MODULE_NOT_FOUND (docker-init.cjs)

**现象**: `zichuan-db-init` 容器启动即报 `Cannot find module '/app/scripts/docker-init.cjs'`。

**根因**:
1. `docker-compose.yml` 第 60 行把 `./scripts/docker-init.cjs` 挂进容器、第 62 行执行它,但该文件从未创建(目录只有 `db-init.js` 等)。
2. 根目录没有 `.env`,而 `app`/`db-init` 服务靠 `env_file: - .env` 读 `DOCKER_DATABASE_URL`、`SESSION_SECRET` 等,缺失会导致后续 migrate/seed 变量为空失败。

**修复**:
- 新建 `scripts/docker-init.cjs`(CommonJS,.cjs 因 package.json 为 type:module):用 `net` 探测 MySQL 端口就绪(取代原 `sleep 10`),再用 @prisma/client 兜底执行 `CREATE DATABASE IF NOT EXISTS`(失败不阻断)。
- 新建 `.env`:含 `DATABASE_URL`(localhost:3308)、`DOCKER_DATABASE_URL`(mysql:3306)、`SESSION_SECRET`(随机 32 字节 hex)、`NODE_ENV=production`、`MYSQL_HOST_PORT=3308`、`NGINX_HOST_PORT=80`。`.env` 已在 .gitignore 中。
- `docker-compose.yml` 移除冗余的 `sleep 10`。

**验证**: `node --check` 通过; `docker compose config` 通过。

**说明**: mysql 容器本身已通过 `MYSQL_DATABASE: asset-manage` 自动建库,docker-init 主要做就绪等待 + 兜底。后续若 db-init 仍失败,排查方向为镜像内 @prisma/client 是否齐备(应在 Dockerfile runner 阶段已 COPY `node_modules/@prisma` 与 `node_modules/.prisma`)。

## docker-init.cjs 服务器部署报错（scripts 被整目录忽略）

- 现象：服务器 git 部署后 `db-init` 报 `Cannot find module '/app/scripts/docker-init.cjs'`（与本地最初报错一致）。
- 根因：`.gitignore` 与 `.dockerignore` 都整目录忽略了 `scripts/`，`docker-init.cjs` 从未进 git；`db-init` 通过**宿主机 bind mount** 挂这个文件，服务器缺失该文件 → Docker 在容器内建同名空目录 → MODULE_NOT_FOUND。
- 修复（已提交 `d789d41`）：`.gitignore` 改为仅忽略本地开发脚本（db-empty/db-init/health-check/kill-node/prisma-generate/test-db）、保留 `docker-init.cjs`；`.dockerignore` 移除 `scripts`；`Dockerfile` 将脚本 `COPY` 进镜像；`docker-compose.yml` 删除 `db-init` 的 bind mount，运行时改用镜像内脚本。→ 不再依赖宿主机文件。
- 注意：`.env` 仍被 gitignore（含 SESSION_SECRET 密钥），**服务器需手动创建 `.env`**，否则 migrate/seed 会因变量为空失败。

## 局域网 Debian 服务器(192.168.110.145)部署 502 排查

- 部署目标：局域网 Debian 服务器，IP **192.168.110.145**（非本机 mac 的 192.168.110.142），docker compose 部署；用户通过 IP 访问报 **502 Bad Gateway**。
- 502 含义：nginx 已响应（80 端口通、IP 可达、防火墙可排除），仅反向代理到上游失败。docker 下两个主因：
  1. nginx upstream 写成 `127.0.0.1:3000`（若误挂 `nginx-zichuan.conf`）→ 容器内指回 nginx 自己 → 502。**仓库默认 compose 挂的是 `docker/nginx/default.conf`（`app:3000` 服务名，正确），切勿改用 `nginx-zichuan.conf` 挂载**。
  2. app 容器未起/崩溃/未监听 3000（常见于 `.env` 的 `DOCKER_DATABASE_URL` 错或 mysql 未 ready）→ nginx 连不上 app → 502。
- 服务器诊断命令：`docker exec zichuan-nginx cat /etc/nginx/conf.d/default.conf`、`docker compose ps`、`docker logs --tail 30 zichuan-app`、`docker logs --tail 30 zichuan-nginx`。
- **实际定位（用户贴 145 日志）**：nginx 配置正确（app:3000、server_name _，排除原因A）；app 日志 Next.js `Ready` 监听 0.0.0.0:3000。nginx 报错 `connect() failed (113: Host is unreachable) ... upstream: http://172.18.0.4:3000/`。根因 = nginx 缓存了 app 的旧容器 IP（145 上 nginx Up 20min > app Up 10min，启动顺序错位 / app 重建换 IP），解析到的 172.18.0.4 现已不可达。修复：`docker compose restart nginx` 重新解析 DNS；验证 `docker exec zichuan-nginx wget -q -O /dev/null http://app:3000/`。若仍不通查 `docker network inspect`（确认 app/nginx 同网络、IP 一致）。

## TDD 修复导出 Excel 内容为 [object Object]（/tdd）

- 现象：设备列表导出 Excel 保存后文件无内容/显示 `[Object. object]`。
- 根因：server action `exportAssetsToExcel` 等返回 Node `Buffer`，经 Next server action 序列化到客户端变成 `{type:'Buffer', data:number[]}` 普通对象；客户端 `new Blob([obj])` 字符串化为 `"[object Object]"`，文件损坏。导入侧早已用 `Array.from(new Uint8Array(...))` 转 number[] 规避，导出侧未遵守同一约定。
- 修复：新增 `src/lib/excel-download.ts`（纯函数 `bufferToBytes` 统一处理 {type:'Buffer',data}/number[]/Uint8Array→Uint8Array；`downloadExcelFile` 封装 Blob+下载）；`excel.actions.ts` 三个导出函数返回值由 `Buffer.from(buf)` 改为 `Array.from(buf)`（类型 `buffer: number[]`）；asset-list/employee-list/settings/models 共 4 处客户端 `new Blob([result.data.buffer])` 改为 `downloadExcelFile(result.data.fileName, result.data.buffer)`。
- 测试：`tests/excel-buffer.test.ts` 验证三种形态转换正确且 `Blob.size` 等于字节数（非 `[object Object]` 长度）。tsc 通过，前端测试 36 个全绿。
