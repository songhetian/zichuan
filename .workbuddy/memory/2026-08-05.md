## 修复 `npm run docker:deploy` 报错 MODULE_NOT_FOUND (docker-init.cjs)

**现象**: `zichuan-db-init` 容器启动即报 `Cannot find module '/app/scripts/docker-init.cjs'`。

**根因**:
1. `docker-compose.yml` 第 60 行把 `./scripts/docker-init.cjs` 挂进容器、第 62 行执行它,但该文件从未创建(目录只有 `db-init.js` 等)。
2. 根目录没有 `.env`,而 `app`/`db-init` 服务靠 `env_file: - .env` 读 `DOCKER_DATABASE_URL`、`SESSION_SECRET` 等,缺失会导致后续 migrate/seed 变量为空失败。

**修复**:
- 新建 `scripts/docker-init.cjs`(CommonJS,.cjs 因 package.json 为 type:module):用 `net` 探测 MySQL 端口就绪(取代原 `sleep 10`),再用 @prisma/client 兜底执行 `CREATE DATABASE IF NOT EXISTS`(失败不阻断)。
- 新建 `.env`:含 `DATABASE_URL`(localhost:3308)、`DOCKER_DATABASE_URL`(mysql:3306)、`SESSION_SECRET`(随机 32 字节 hex)、`NODE_ENV=production`、`MYSQL_HOST_PORT=3308`、`NGINX_HOST_PORT=80`。`.env` 已在 .gitignore 中。
- `docker-compose.yml` 移除冗余的 `sleep 10`。

**验证**: `node --check` 通过; `docker compose config` 通过。

**说明**: mysql 容器本身已通过 `MYSQL_DATABASE: asset-manage` 自动建库,docker-init 主要做就绪等待 + 兜底。后续若 db-init 仍失败,排查方向为镜像内 @prisma/client 是否齐备(应在 Dockerfile runner 阶段已 COPY `node_modules/@prisma` 与 `node_modules/.prisma`)。

## TDD 修复设备列表 4 个 UX bug（/tdd）

按 TDD 红→绿逐切片修复，新增测试均通过（共 31 个前端组件测试绿，tsc 通过）。

### 切片1：下拉搜索无效(#2) + 宽度太小(#4) — `src/components/ui/searchable-select.tsx`
- 根因：搜索框用的是普通 `<input>`，cmdk 的过滤状态收不到输入 → 搜索无效；`PopoverContent` 用 `w-[--radix-popover-trigger-width]` 把弹层锁死成触发按钮宽度 → 选项文字截断。
- 修复：普通 input 换成 `<CommandPrimitive.Input>`（自动驱动 cmdk 过滤）；宽度改为 `min-w-[var(--radix-popover-trigger-width)] max-w-[min(90vw,360px)]`。
- 测试：`tests/searchable-select.test.tsx`（输入关键字仅显示匹配项 / 弹层不再锁宽）。

### 切片2：内存/硬盘容量筛选无效(#1) — `src/app/(main)/assets/asset-list-client.tsx` + 新 `src/lib/asset-filter.ts`
- 根因：筛选用**型号名关键词**（`name.includes("内存"/"ddr"/...)`）判定内存/硬盘，而配置摘要 `getConfigSummary` 用的是**分类名** `cat === "内存"`，口径不一致 → 型号名不含关键词的内存条被漏判，设了最小值后整列被错误过滤。
- 修复：抽出纯函数 `getMemoryGB/getDiskGB/extractCapacityGB`（按分类名为主、型号名关键词兜底），筛选与配置摘要共用，保证口径一致。

### 切片3：高级搜索直接展示(#3) — `asset-list-client.tsx`
- 修复：把高级筛选折叠区抽成导出的 `AdvancedFilterBar` 展示组件，移除折叠开关 `advancedFilterOpen`，改为始终渲染（部门/员工/内存/硬盘四控件直接可见）。
- 测试：`tests/advanced-filter.test.tsx`。

### 测试基础设施
- 新增 `vitest.frontend.config.ts`：仅加载 `tests/setup-frontend.ts`（不连 DB），使纯 UI 组件测试不依赖 MySQL；package.json 增加 `test:frontend` 脚本。
- `tests/setup-frontend.ts` 增加 jsdom polyfill：`ResizeObserver`、`Element.prototype.scrollIntoView`（cmdk/Radix 需要）。
