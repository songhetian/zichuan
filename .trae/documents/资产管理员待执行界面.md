# 资产管理员「待执行变更」界面

## Context（背景）
升级/降级配件的 ASSET_UPGRADE 流程：发起人只给「设备 + 配件类别 + 动作(升级/降级) + 原因」，**审批通过后不再自动改配件**（完全手动执行）。实际的配件 更换/增加/减少 由资产管理员在审批通过后，通过「待执行变更」页手动执行（含库存增减+流水+生命周期日志），执行后在申请单标记「已执行」防重复。

### 本轮确认的设计决策（用户拍板）
1. **执行绑定资产管理员**：只有流程**末节点配置为「角色=资产管理员(ASSET_MANAGER)」**的申请，审批通过后才进入待执行列表并可执行；配置里没有该末节点 → 通过后不可执行（不校验、不进入列表）。执行权限按角色 `asset.manage` 兜底（多个账号持有该角色均视为资产管理员，可执行——与审批多账号同理）。
2. **完全移除自动执行**：ASSET_UPGRADE 末节点审批通过**只**把单置为 `APPROVED`，不调用 `executeUpgradeOnApproval`、不改配件、不释放资产预占、不记 UPGRADED 日志；资产保持预占直到资产管理员在执行页执行时统一处理（改配件 + 库存流水 + UPGRADED 日志 + 释放预占 + 写 executedAt）。ASSET_SCRAP 流程保持原有自动执行不动。

---

## 1. 数据标记（migration m10）
- `prisma/schema.prisma` 的 `ApprovalRequest` 新增两列：
  - `executedAt DateTime?` —— 执行完成时间，NULL = 待执行。
  - `finalNodeRole String?` —— ASSET_UPGRADE 末节点审批角色 key（`ASSET_MANAGER`），用于"末节点必须是资产管理员"的过滤；SCRAP 不填。
- 走 migration（仓库用 migrations m1–m9，不用 `db push`）：
  - 新建 `prisma/migrations/<ts>_m10_approval_execution/migration.sql`：
    `ALTER TABLE \`ApprovalRequest\` ADD COLUMN \`executedAt\` DATETIME NULL, ADD COLUMN \`finalNodeRole\` VARCHAR(64) NULL;`
  - 执行 `npx prisma migrate dev --name m10_approval_execution`；测试库 `npm run db migrate`。
- 两列均可空 → 老单自然进待执行列表判断口径：`executedAt IS NULL`（符合预期）；`tests/setup.ts` 截断逻辑无需改动。

## 2. 引擎改动：移除 ASSET_UPGRADE 自动执行
`src/actions/approval.actions.ts` 的 `approveTask` 末节点分支（`nextNode==null`，约 L786-831）改为：
- 末节点通过仍置 `status:"APPROVED", currentNodeId:null, finishedAt:now` + APPROVE 日志。
- **ASSET_SCRAP**：照旧 `executeScrapOnApproval(tx,...)` + EXECUTE 日志（不动）。
- **ASSET_UPGRADE**：
  - **不再调用 `executeUpgradeOnApproval`**，删除 EXECUTE 日志分支。
  - 写入 `finalNodeRole = node.assigneeRole`（末节点角色），见 L795 附近 update 的 data 里加 `finalNodeRole`。
  - 资产**保持预占**（不释放）——本次不触碰 asset。
- 这样末节点是 `ASSET_MANAGER` 的单才具备执行条件；不是则不进入待执行列表。

## 3. 抽公共库复用现有配件调整
- 新建 `src/lib/component-adjust.ts`，导出 `applyComponentAdjustments(tx, ctx): Promise<string>`：
  - `ctx = { assetId, adjustments:[{modelId,quantityDelta}], operator, remark?, requestId?, assetStatus }`。
  - 内容 = 现 `adjustAssetComponents`（src/actions/lifecycle.actions.ts L776-890）的事务体：判库存、增删 `assetComponent`、写 `UPGRADE_USE`(负数)/`UPGRADE_RETURN`(正数) 流水、lifecycleLog(`UPGRADED`，本项目加 `requestId` 追溯)，返回变更摘要字符串。
  - `asset.status` 由 `assetStatus` 入参传入，避免库内重复查 asset。
- 重构 `adjustAssetComponents` 为薄封装：事务外做 `requireAuth`+schema 校验+预查 asset/models+`systemLog`，事务内调库函数。**逐字保留**错误 map（`STOCK_INSUFFICIENT/COMPONENT_NOT_FOUND/QUANTITY_INSUFFICIENT`）、`operator` 必填、库存符号、摘要格式 `remark（<summary>）`——这是 `tests/adjust-components.test.ts`(13 用例) 与 `tests/lifecycle.test.ts` 断言的字符串。
- 落地顺序：先写库函数→改 wrapper→全测回归（`npx vitest run`）确认 0 回归再继续。

## 4. 新执行动作 `src/actions/approval-execute.actions.ts`
- `executable` 判定常量：`finalNodeRole === "ASSET_MANAGER"`。
- `executeApprovedChange(requestId, adjustments)`（`ActionResult<{requestId, executedAt}>`）：
  - `requireAuth` + `guardPermission(user, "asset.manage")`。
  - zod 校验 adjustments（复用 `adjustComponentsSchema` 形状）。
  - 单事务内：
    1. 条件更新 `approvalRequest.updateMany({ where:{ id, status:"APPROVED", businessType:"ASSET_UPGRADE", finalNodeRole:"ASSET_MANAGER", executedAt:null }, data:{executedAt:now} })`，count=0 → 抛错（幂等/防并发/非资产管理员末节点）。
    2. 解析 payload（assetId/componentCategoryId/action/reason，兼容 JSON 字符串）；查 asset；按 categoryId 校验该类别在设备现有配件。
    3. 调 `applyComponentAdjustments(tx,{...,requestId,assetStatus})` 改配件+写流水。
    4. **释放资产预占**：`asset.update({ status: reservedFromStatus ?? status, reservedByRequestId:null, reservedFromStatus:null })`。
  - 错误返回：非 APPROVED/已执行/末节点非资产管理员 → `"申请单不满足执行条件或已执行"`；库存不足等 → 复用库抛错映射。
- `getPendingExecutionRequests()`：`requireAuth` + `guardPermission(asset.manage)`；`approvalRequest.findMany({ where:{ status:"APPROVED", businessType:"ASSET_UPGRADE", finalNodeRole:"ASSET_MANAGER", executedAt:null }, orderBy:{submittedAt:"desc"} })`，返回 `{ id, requestNo, title, submittedAt, assetId, assetNo, assetName, categoryId, action, reason }`（payload 快照 + `payload.assetId↔asset` 联查补全）。

## 5. 前端
- `src/app/(main)/approvals/execute/page.tsx`（`export const dynamic="force-dynamic"`）：服务端调 `getPendingExecutionRequests` + 查每个后续相关设备当前配件与该品类可选型号，渲染 `ExecuteClient`；无 `asset.manage` 时 action 拒绝（页面给空态/提示）。
- `src/app/(main)/approvals/execute/execute-client.tsx`：列表每行展示 设备(assetNo·name)/配件类别(action 标签)/申请原因/提交时间 + 「执行」按钮；点击弹窗（ui/dialog、badge、select、input）：显示申请信息 + 该设备当前配件，资产管理员通过「选该类别下新增型号+数量」「减少/移除该类别现有型号」生成 `adjustments`；提交调 `executeApprovedChange`，成功 `router.refresh()`。
- 导航：`src/components/layout/sidebar.tsx` 的「审批中心」children 追加 `{ href:"/approvals/execute", label:"待执行变更" }`。菜单对所有人可见、权限在 action 层 `guardPermission` 兜底（与既有项一致）。
